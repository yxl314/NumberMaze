# stacklog 改进提案（对标仓内 CDBurn Logger 的能力吸收）

日期：2026-10-12
读者假设：**未见过仓内 `Source/CDBurn/Tools/Logger/`**。因此本篇对每条拟吸收的能力
都完整描述那边的做法（机制、算法、配置、教训动机）、吸收后的预期效果、以及在 stacklog
的落地方案。

设计前提（红线，全篇不得违背）：stacklog 的立身之本是**热路径无锁无分配 + 每线程
SPSC 环形缓冲 + 后台异步排空 + 逻辑调用链（span 树）+ 零第三方依赖 + C++11 可移植**。
下面所有改进都必须在不动摇这些支柱的前提下做；凡是需要"引入锁 / 引入 Qt / 改成同步
直写"的方案，一律不采纳。

## 一、总览对比

| 能力 | CDBurn Logger（`Source/CDBurn/Tools/Logger`） | stacklog 现状 | 判定 |
|---|---|---|---|
| 定位 | Qt 应用的**人读文本日志**：同步直写、单文件轮转、终端镜像 | **逻辑调用链追踪库**：跨线程 span 树、异步、人机两读 | 定位不同，互补 |
| 落盘轮转 | **有**：单文件上限 + 保留 N 份 + 启动即轮转 + 归档失败退化 | **无**：`FileSink` 纯追加，永不轮转 | stacklog 缺 → §三 |
| 落盘可靠性 | **有**：自动建目录、初始化试探写、写失败转终端、提示只一次 | 目录不建；写失败只诊断一次即丢记录 | stacklog 缺 → §四 |
| 刷盘/崩溃安全 | 每条即 `flush`："崩溃不丢已返回的日志" | 异步 100ms 批量（有丢失窗口） | 需可配 → §五 |
| 时间戳 | **人类可读**本地时间 `yyyy-MM-dd HH:mm:ss.zzz` | 原始纳秒（steady+wall），人不可读 | stacklog 缺渲染 → §六 |
| 终端输出 | **彩色** stderr + `NO_COLOR`/`isatty` 检测 + 文件/终端双写 | 纯文本 stderr，无颜色，无 tee | stacklog 缺 → §七 |
| 级别 | 4 级 + **发布版编译期剥离 DEBUG**（参数不求值） | 4 级 + 运行期阈值，无编译期剥离 | stacklog 缺 → §九 |
| 错误记录结构 | **三要素**：错误码 + 可读原因 + 后端原始输出 | 仅一条文本消息 | stacklog 缺 → §八 |
| 参数检查宏 | `CHECK_ERROR/WARNING` 家族：记日志 + return，发布版恒生效 | 无 | stacklog 缺（可选）→ §十 |
| 默认日志路径 | **有**：XDG State Dir 三级回退 + 自动建目录 | 无（调用方自备完整路径） | stacklog 缺 → §十一 |
| 记录文件兼容 | 不适用（只写文本） | 无魔数/版本，纯按 `sizeof(Record)` 读写 | stacklog 缺（地基）→ §二 |
| 追踪模型 | traceId/opId/parentId 字符串列 + capture/restore | `ChainId`/`SpanId` 定长结构 + capture/attach + **离线建树/孤儿/冲突诊断** | **stacklog 强** |
| 热路径 | 全局单锁同步直写 | 线程局部无锁环，生产者不取锁不分配 | **stacklog 强** |
| 结构化输出 | 无（仅单行文本） | 定长 `Record` 二进制 + JSON 树渲染 + 解析 CLI | **stacklog 强** |
| i18n | `Q_DECLARE_TR_FUNCTIONS` + `tr()` 全量 | 无（硬编码中文） | 定位不同，不吸收 → §十三 |
| 平台/依赖 | Qt 5.6 | 零依赖 C++11 + 可选 POSIX fork 适配 | **stacklog 强** |

## 二、P0-1 记录文件版本与魔数（其余改进的地基）

### 为什么必须最先做

`RecordFileSink` 以 `fwrite(&record, sizeof(Record), 1)` 写定长块，`RecordFileReader`
按字节 `fread` 读回，只有恰好读满一块才算一条（`src/io/record_file.cpp:23-33,69-95`）。
**文件里没有任何魔数/版本号**，字段一旦增删（§八结构化错误就要动 `Record`）旧文件会被
静默误读或全量报"截断"。设计文档也自认"字段变更需重新生成文件"（`docs/树解析器设计.md:173-176`）。
这是本项目里**唯一一处"改了代码就悄悄破坏存量数据"**的地方，必须先堵。

### 预期效果

- reader 打开非本库、或旧版本生成的文件 → 明确报错（含期望版本/实际值），而不是把
  ASCII 文本当成 Record 乱解析。
- `Record` 的结构体大小、字节对齐有 `static_assert` 保护，改字段编译期即失败。
- 后续 §八 扩展字段时，老文件的读者行为可预期（拒绝或按版本兼容）。

### 落地方案

- **文件头块**（推荐，优于逐条魔数，零每记录开销）：`RecordFileSink` 打开即写一个固定
  头部（magic `uint32` + format_version `uint16` + `sizeof(Record)` `uint16` + 保留），
  `RecordFileReader` 读回并校验；版本不符 → `error_` 报清晰原因。
- `Record` 上补 `static_assert(sizeof(Record) == <当前值>)` 与对齐断言（设计文档声称
  296 字节，代码并无保护，`docs/树解析器设计.md:33`）。
- 保持"末尾残块 vs 读错误分开上报"的既有区分（`src/io/record_file.cpp:81-93`），新增
  "头部非法"作为第三类错误串。
- 补测试：读入文本文件、读入截断头部、读入旧版本头部 → 三种都被明确拒绝。

## 三、P0-2 文件轮转与保留

### CDBurn Logger 的做法（完整机制）

配置四元组 `LoggerConfig(t_log_dir, t_log_base_name, t_max_file_size, t_max_files)`
（`Logger.h:27-45`），默认 **5 MB × 5 份**。轮转语义（`Logger.cpp:194-249`）：

- 现行文件 `<基础名>.log`，归档为 `<基础名>.log.1` … `.log.N`；轮转时先把最老的
  `.N` 删除，然后 **rename 链整体后移**（`.N-1→.N` … `.1→.2`），最后现行 →`.1`；
  全部用 `QFile::rename`，**禁 `system("mv")`**。
- **缺环不算失败**：源文件不存在视为成功（历史链有缺口不是故障，`Logger.cpp:174-190`）。
- **归档失败退化策略**：目标被占/目录只读时，现行文件仍可写→**继续追加、本进程不再
  尝试轮转**（避免逐行重跑归档链），并**只提示一次**；一旦某次归档成功即复位，下次
  异常可再提示（`Logger.cpp:232-247`）。
- **无条件重开现行文件**：归档失败也绝不留在"已关闭"态；重开失败才停用文件通道
  （`Logger.cpp:220-230`）。
- **启动即轮转**：init 时若既有文件已超上限，不等第一条业务日志就先轮转
  （`Logger.cpp:396-404`）。
- 记账用**追加字节数累加**，不再每行 `fstat`（`Logger.cpp:271-272`）。

### stacklog 现状

`FileSink` 以 `"ab"` 追加打开（`src/io/sink.cpp:116`），无任何大小/份数概念，也无论转。

### 预期效果

- `log_to_file` 可配单文件上限与保留份数；超限自动轮转，磁盘占用有界。
- 归档失败（只读目录/目标被占）时**继续写现行文件、日志不丢**，只提示一次。
- 启动即对已超限的存量日志轮转，不需等新记录。

### 落地方案

- 新增 `RotatingFileSink`（或给 `FileSink` 加 `(path, max_bytes, max_files)` 构造）：
  写路径与 `FileSink` 共用，字节数累加，超限时执行同款 rename 链；把上面四条策略
  （缺环成功、失败停轮转并复位、无条件重开、启动即轮转）原样搬过来。
- **与异步架构的交互**：写入恒在排空线程（同一时刻只有一个 sink 写者，见 `io/sink.hpp`
  的"write 同一时刻只有一个调用者"约定），轮转天然串行，**不需要额外锁**——这比
  Logger 的"持 `t_mutex` 期间轮转"更干净。
- **二进制 sink 同样要轮转**，且必须**整条记录边界切分**（writer 一次一条，容易保证）；
  `RecordFileReader` 对"当前文件 + 归档"的读取策略另行文档化（可只读现行）。
- 多进程写同一文件仍不在范围（Logger 亦然，无文件锁）——文档写明。
- 配置进 API：`log_to_file(path, opts)` 或 `RotatingOptions{max_bytes,max_files}`。

## 四、P0-3 落盘可靠性：建目录、试探写、写失败降级

### CDBurn Logger 的做法

- **自动建目录**：init 时 `QDir().mkpath(dir)`（`Logger.cpp:364`）。
- **初始化试探写**："打开文件并试探写判真能写"——写一条 `LOGGER_INIT` 横幅并核对
  写入字节数，失败即 `init` 返回 false（`Logger.h:130-133`、`Logger.cpp:376-393`）。
- **写失败转终端**：单行写入不完整（磁盘满/坏）时，本行转嫁 stderr，不静默丢行
  （`Logger.cpp:277-281,296-300`）。
- **未就绪降级**：未 init 或已 shutdown → 输出到 stderr，且**只提示一次**
  （`QAtomicInt` 的 `testAndSet`，`Logger.cpp:171,285-293`）。
- **持锁期不写阻塞终端**：归档/降级等阻塞式 stderr 提示在锁内只入队，**出锁后统一补打**，
  避免某线程卡在 stderr 时占着锁拖住全部线程与 shutdown（`Logger.cpp:157-165,252-253,282`）。

### stacklog 现状

`log_to_file` 直接 `new FileSink` 打开（`src/logger.cpp:32-51`），**不建父目录**；
`FileSink::write` 失败只诊断一次（`src/io/sink.cpp:136-152`）——诊断后记录就丢了，
不会兜底到 stderr。

### 预期效果

- 目标目录不存在时 `log_to_file` 自动创建，返回成功。
- 文件写失败后，记录**兜底到内置 stderr sink**（而不是丢），且只提示一次。
- 初始化无法写时 `log_to_file` 返回 false，不产生半开状态。

### 落地方案

- `log_to_file` 内 `mkpath` 父目录（纯 stdlib/自身 fs 辅助，保持零依赖）。
- `FileSink` 写失败达到"持久失败"判据后，切换到默认 stderr sink（保留诊断一次 + 一次性
  提示）；与 §三 的"归档失败继续追加"不冲突：写失败与归档失败是两类退化。
- stderr 兜底提示走"只提示一次"闸门（原子标志）。
- 因为 stderr 兜底发生在排空线程而非热路径，无需像 Logger 那样"出锁后补打"，但**排空
  线程内不得长时间阻塞在 stderr** 的原则仍要守住（写入失败即切 sink，不再逐条重试）。

## 五、P1 刷盘/崩溃安全策略可配

### CDBurn Logger 的做法

每条日志写完立即 `flush()`（`Logger.cpp:269-270`），明确动机写进注释："同步直写：每条
即 flush，崩溃不丢已返回的日志"。代价是吞吐低。

### stacklog 现状

后台线程每 100 ms 排空一次（默认，`logger.hpp:41`；`src/detail/state.cpp:71-86`）。
异步换吞吐，但**崩溃窗口 = 环形缓冲里未落盘的记录 + 最后 100ms**。

### 预期效果

- 想"错误日志必须落盘"的用户可配 `flush_on_level(error)`，ERROR 级记录**立即排空**。
- 需要逐条持久化（排障/崩溃现场）时可切**同步模式**，行为对齐 Logger。
- 默认仍是异步，热路径特性不变。

### 落地方案

- 新增 `set_flush_on_level(Level)`：当记录级别 ≥ 阈值时，生产线程/排空线程立即触发一次
  排空（可复用现有唤醒条件变量 `FlusherState`，`src/detail/state.cpp:41-86`）。
- 新增 `set_sync_mode(bool)`：为 true 时 `commit` 后同步排空本环（仅调试/排障用，文档
  写明吞吐下降）。
- `flush()` 现有语义保持；二者都只是"何时排空"的策略，不改无锁生产路径。

## 六、P1 人类可读时间戳

### CDBurn Logger 的做法

文本行首列就是本地时间 `QDateTime::currentDateTime().toString("yyyy-MM-dd HH:mm:ss.zzz")`
（`Logger.cpp:112`），人眼/编辑器直接可读。

### stacklog 现状

`Record` 双时间戳：steady（单调，算时长）+ wall（纳秒，`core/record.hpp:53-54`），
但 `format_record` 原样打纳秒（`src/io/sink.cpp:86-111`），人读不友好。

### 预期效果

- 文本 sink 输出的首列（或 wall 列）渲染为 `YYYY-MM-DD HH:MM:SS.mmm`（本地时区），
  与纳秒值一致（±1s）。
- JSON 渲染可选同样给出可读时间；二进制格式**不变**（保持纳秒原值）。

### 落地方案

- 只在**渲染层**（`format_record`、`render_json`）加人类可读转换，`Record` 布局与
  二进制写盘不动。
- 现成的 `common::time`（`src/common/time.cpp:10-20`）加一个 wall-ns → 可读串的纯函数；
  时区取本地（`localtime_r`，非 POSIX 退 UTC，写明）。

## 七、P1 终端彩色 + 能力检测 + 双写（tee）

### CDBurn Logger 的做法

- 四级异色：DEBUG 灰 / INFO 绿 / WARN 黄 / ERROR 亮红（ANSI，`Logger.cpp:123-138`）。
- **能力检测**：`NO_COLOR` 非空即禁色（业界约定）；仅 `isatty(stderr)` 才染色
  （`Logger.cpp:141-148`）。每次现判，不缓存。
- 双通道：**文件（纯文本）+ 终端（彩色）同时输出**，终端慢不拖累文件写入
  （`Logger.cpp:150-155,300`）。

### stacklog 现状

`StderrSink` 纯文本无颜色（`src/io/sink.cpp:45-64`）；`FileSink` 只落文件；二者不能同时
输出。

### 预期效果

- 交互终端下四级异色；`NO_COLOR=1` 或重定向/管道时自动无色。
- 可同时"落文件 + 打终端"（`TeeSink`），排障时不必二选一。

### 落地方案

- `StderrSink` 加彩色开关（默认自动检测：`isatty(stderr)` 且 `NO_COLOR` 为空）。
- 新增 `TeeSink`（组合两个 sink，先主后镜像；镜像失败不影响主）。零依赖、无锁假设不变
  （写入仍在排空线程单点）。
- 颜色常量按级别映射，风格对齐 Logger（灰/绿/黄/亮红）。

## 八、P1 结构化错误记录

### CDBurn Logger 的做法

`LOG_ERROR(code, reason, raw)` 三要素：错误码（`0x%08X` 渲染）+ 可读原因 + 后端原始
输出，文本行里以 `code=... reason=... raw=...` 落盘（`Logger.h:163-169`、
`Logger.cpp:463-471`）。错误**不是**一句糊在一起的文本，事后可机检/检索。

### stacklog 现状

只有 `Level::error` 的一条文本消息（`core/record.hpp:14-20`），错误码/后端原始输出无处承载。

### 预期效果

- `log_error(code, reason, raw)` 产出一条带错误码的事件记录。
- 文本渲染含 `code=0x%08X reason=... raw=...`；JSON 含同名字段。
- 老版本二进制文件仍可读（依赖 §二 版本化）。

### 落地方案

- 在 §二 版本化之后，给 `Record` 增 `uint32_t code`（或用一个 `Kind::error_detail` 记录
  承载，避免动主结构——二选一，推荐前者配版本升级）。
- API：`void log_error(uint32_t code, const char* reason, const char* raw)` + 宏
  `LOG_ERROR(code, reason, raw)`（与 Logger 命名一致，读者平滑）。
- 复用内置容量宏截断策略（`core/record.hpp:31-42`）。

## 九、P2 编译期裁剪（发布版剥离事件记录）

### CDBurn Logger 的做法

`QT_NO_DEBUG` 下 `LOG_DEBUG(v_msg)` 展开为 `((void)0)`——**参数不求值、零开销**；其余
级别恒在（`Logger.h:172-177`）。

### stacklog 现状

只有运行期阈值（`set_level` + `SL_LOGF_` 宏先判 `enabled()`），debug 事件的格式化在
运行期被跳过，但**符号与判级成本仍在**。

### 收敛红线

stacklog 的 **enter/exit 结构记录必须始终产生、不受级别/裁剪影响**（`docs/项目设计.md:86-89`），
否则离线树会残缺。所以裁剪**只能作用于事件记录（event）**。

### 预期效果

- `-DSTACKLOG_MIN_LEVEL=warn`（或 `NDEBUG` 下默认剥离 debug 事件）→ debug 事件零符号，
  `SL_SPAN`/`SL_FUNCTION` 的 enter/exit 仍成对产生，`stacklog_tree` 建出的树完整。

### 落地方案

- 宏层：`LOG_DEBUG` 等在编译期低于阈值时展开空操作，参数不求值；`SL_SPAN` 等结构宏
  不参与裁剪。
- 提供 `STACKLOG_MIN_LEVEL` 编译期宏（默认 debug，即不裁）。

## 十、P2 运行时参数检查宏（可选）

### CDBurn Logger 的做法

`Check.h` 把"判非法 → 记日志 → 去向"压成一行（体感近 `assert`，但**发布版恒生效**——
参数非法不该崩进程）：`CHECK_GUARD` 骨架 + `CHECK_ERROR`/`CHECK_ERROR_VOID`（记
`LOG_ERROR` 后 return 错误码/void）、`CHECK_WARNING`/`CHECK_WARNING_VOID`、`CHECK`
（只记不改流程）。条件为假的**原文**由 `#v_cond` 自动生成，调用方不写；级别按"内部契约
违反=ERROR / 预期内拒绝=WARNING"分工（`Check.h:1-84`）。

### stacklog 现状

无任何校验宏，调用方各写各的（空消息/空格式只计入丢弃计数，`src/logger.cpp:80-85,94-98`）。

### 预期效果

- 参数非法时"记一条 error 事件 + 按族返回/继续"，进程不崩、不静默。

### 落地方案

- 提供 `SL_CHECK(cond, msg)`（记 error event，继续）、`SL_CHECK_RET(cond, code, msg)`、
  `SL_CHECK_VOID(cond, msg)`。条件原文可选用 `#cond` 自动附上，调用方仍可给人话 `msg`。
- 映射到 stacklog 的 event 记录 + `Level::error`；不改结构记录。
- 定位为**可选**：库不与"断言/终止"绑定。

## 十一、P2 默认日志路径与便捷 API

### CDBurn Logger 的做法

`default_log_dir()` 三级回退：`XDG_STATE_HOME`（非空且绝对路径）→ `$HOME/.local/state`
→ `QDir::homePath()`，末尾挂应用子目录（`Logger.cpp:573-588`）；配合 §四 的自动建目录，
实现"零配置就能写到一个合规位置"。

### stacklog 现状

`log_to_file(path)` 要求调用方给完整路径；无默认位置概念。

### 预期效果

- `default_log_path("myapp")` 返回合规默认路径；`log_to_app_dir("myapp")` 一步落盘。

### 落地方案

- 纯 `getenv` 实现同款三级回退（非 POSIX 平台退 `$HOME`/当前目录，写明）；返回路径，
  不自动写盘；与 §四 mkpath 配合。

## 十三、明确不吸收

- **Qt 依赖与 `tr()` i18n**：stacklog 是零依赖库，消息文本由调用方给出；不引入 Qt、
  不接管多语言。
- **同步直写替换异步**：只加"可配刷盘策略"（§五），默认异步不换掉。
- **全局单锁同步**：不吸收；stacklog 的无锁生产路径是核心资产。
- **字符串 id（`T-p123-1`）作为内部表示**：只保留为"展示层渲染"（`to_string` 已有），
  内部仍用定长结构。

## 十四、反向清单（CDBurn Logger 侧可吸收 stacklog 的）

若两边有机会互相借鉴，Logger 值得吸收：逻辑调用链的**跨线程接续 + 离线建树/孤儿诊断**
（现只有 traceId 字符串，无树重建）；**无锁热路径 + 异步排空**（现为同步持锁直写）；
**定长 Record + 二进制结构化文件 + JSON 渲染**；**丢弃计数**（`dropped_records`）
把"丢了日志"暴露出来。是否落地属 Logger 侧议题，本篇不展开。

## 十五、红线

1. 热路径保持无锁无分配：生产者只碰线程局部环，不取锁、不 `new`。
2. 零第三方依赖；C++11；非 POSIX 平台的功能可整体关闭（fork 适配保持现状）。
3. **结构记录（enter/exit）永不过滤、永不编译期裁剪**，保证离线树完整。
4. 任何 `Record` 布局变更必须伴随 §二 的版本/魔数，禁止无声破坏存量二进制文件。
5. 人读渲染（文本/JSON）与机器格式（定长块）分层，互不绑架。

## 十六、实施顺序与验收

1. **§二 版本/魔数 + `static_assert`** → 验收：读入文本文件/截断头部/旧版本头部均被
   明确拒绝（错误串含期望与实际）；`Record` 大小断言生效。
2. **§三 轮转与保留** → 验收：写超上限后只剩 `base` + `base.1..N`；只读目录致归档失败时
   继续追加且只提示一次；启动即对超限存量文件轮转；二进制 sink 整条记录边界切分。
3. **§四 可靠性** → 验收：父目录不存在自动创建；文件写失败后记录兜底到 stderr 且不静默、
   只提示一次；探针式初始化失败 `log_to_file` 返回 false 且无半开状态。
4. **§五 刷盘策略** → 验收：`flush_on_level(error)` 下 error 记录立即可见；`sync_mode`
   下无 100ms 窗口；默认异步行为与热路径开销不变。
5. **§六 时间戳** → 验收：文本行出现可读本地时间且与 wall 纳秒一致（±1s）；二进制不变。
6. **§七 颜色/tee** → 验收：`NO_COLOR=1` 无色、非 tty 无色、tty 下四级异色；Tee 下文件与
   终端同时收到，镜像失败不拖累文件。
7. **§八 结构化错误** → 验收：`log_error` 后文本含 `code=0x%08X reason= raw=`、JSON 含同
   字段；旧文件按版本策略可读或明确拒绝。
8. **§九 编译期裁剪** → 验收：`-DSTACKLOG_MIN_LEVEL=warn` 后 debug 事件零符号，`SL_SPAN`
   的 enter/exit 仍成对、树完整。
9. **§十 检查宏** → 验收：条件为假记 error 事件并按族返回/继续，进程不终止。
10. **§十一 默认路径** → 验收：`XDG_STATE_HOME` 非绝对路径被忽略、`$HOME` 回退、路径含
    应用子目录。
